## 二、有效的做法（按效果从大到小）

### 1. 锁音：`--lock-strength 1.0`
- `H3LockAudioLatent` 设 0.85 时，H3 会自己重唱一遍，口型和原歌对不上；设 1.0 时音频 latent 原样保留。
- 片段音轨和干声的相关度会停在约 0.87～0.92，这是音频 VAE 编解码的固有损耗，不是锁音失败。QA 里的 `ok: False` 看相关度就行。

### 2. 唱完才切
- 口型镜头的切点取「下一句开口前 0.08 秒」和「本句最后一个词结束后 0.02 秒」中较晚的那个；构建脚本里有断言兜底。
- 反应镜头只放在 Suno **实际留出的空隙**里（看词级时间轴，不看歌词里写了什么）。
- 甩镜转场同样不能盖住正在唱的词：合成时用词级时间轴判断，剔除 `[段落标记]` 和全大写的观众喊声。

### 3. 参考图决定画面里出现什么
- **参考图里有的东西，模型一定会画出来**：旧的半身图带手持麦，提示词怎么写都挡嘴。改用无麦的单格脸部裁图 `work/*_face_clean.png` + 立式麦（`--mic stand`）。
- **统一背景**：从擂台全景 `refs/venue.png` 左右各裁一块，作为 `work/stage_a.png` / `stage_b.png`，通过镜头的 `bg` 字段传进去，每个人的所有镜头背后都是同一个场景。不要另外生成背景图，同一张原图的两半才在空间上真正一致。
- **道具归属必须每次写明**：两个人同框时，只要没写「谁拿什么」，模型就会把爱迪生的灯泡塞给特斯拉。要正面描述两个人各自的道具。

### 4. 运镜提示词要写起点
- 只写「slow push-in」会让 H3 从远景开始推；写成「starts on a chest-up medium close-up … gently creeps closer」就能正常推近。
- 避免否定句（「no push-in」），要正面描述画面。
- 手持环绕：机位描述后面接 `, shot on a handheld camera … slowly arcing a few degrees around him`。

### 5. 后期「现场运镜层」（`work/live.json`，0 CCU）
- 手持晃动用 0.2～1.7 Hz 的正弦叠加，每个镜头的随机相位不同；推拉幅度在 2%～4%；换人时用甩镜转场；全片统一调色，加随拍子的灯光闪烁、暗角和颗粒。
- 片子本身已经有运镜的镜头，用 `sway: 0.5` / `drift: 0` 减弱后期的晃动和推拉，避免叠加后晃得太厉害。
- 只靠后期救不了「空间割裂」，它只能让割裂不那么扎眼。

### 6. 远景要靠「标尺」
- 写「wide shot」是弱约束：同一个提示词，4 次里只有 1 次拍成了真远景。
- 有效写法：**观众的后脑勺和拳头占画面下三分之一**，同时对远景镜头关掉特写 LoRA（`closeup_lora: 0`）。
- 「从歌手身后反打」拍不出来：参考图都是正脸，模型总会把脸转向镜头，结果折中成侧脸中景。
- 大全景开头经常有约 1 秒「照着参考图摆拍」的画面，剪辑时用 EDL 的 `in` 跳过就行。

## 三、踩过的坑（排查顺序）

| 现象 | 真正原因 | 现在的防护 |
|---|---|---|
| G4 渲染到一半实例消失 | 另一个本地 agent 借用了我们的 `rap-g4` 会话，跑完自己的任务后按名字把它停了 | 每次运行用唯一的会话名 `rap-g4-<时间戳>`；排查时先看 `~/.config/colab-cli/history/<session>.jsonl` |
| G4 被别的会话停掉（更早一次） | 有人跑了不带 `-s` 的 `colab_meter.py stop`，停掉了「最近的会话」 | `stop` 不带 `-s` / `--all` 直接报错退出 |
| 手动换进去的片段又变回旧版 | 拉取时「大小不同就覆盖」，Drive 上的旧副本盖掉了本地的新文件 | 本地文件比 Drive 副本新时保留本地文件（`⏭️ Kept local`） |
| Suno 返回 400 | 歌词「fifty grand」被当成制作人署名 | 改成「fifty thousand」；失败的请求不扣额度 |
| 最后一句被对齐成 5 秒长 | Suno 跳过了写好的观众段，对齐器把上一个词拉长到整个空隙 | 保守处理：镜头留在歌手身上。音量和频谱平坦度都分不清是观众还是歌手 |
| 后台任务显示退出码 0 但实际失败 | 外层 shell 的退出码不代表脚本的退出码 | 一律读日志里的 `exit=` |
| 本地口型评测报「no audio」 | 参照干声只在 G4 上切过 | 本地先用 `cut_audio()` 重新切一份 |

## 四、还没达到预期的地方（下一集要解决）

1. **远景不稳定**：8 句远景口型镜头里，真正的远景只有 3 个，其余是双人中远景。下一步可以试：远景单独用更大的画幅生成，或者先生成一张远景首帧再做图生视频。
2. **反应镜头是 v2 复用的旧素材**：观众、DJ 这些非口型镜头没有统一背景，风格和新口型镜头有差距。
3. **分辨率偏低**：H3 原生输出 1344×768。目前靠上传前 Lanczos 放大到 1920×1080（竖版 1080×1920）凑合，画面偏软。
4. **个别瑕疵**：B01 特斯拉手里的道具看起来像灯泡；A16 从全身远景开始推镜，前 2 秒嘴太小。
5. **空间关系仍然靠运气**：两人谁站左、谁站右没有固定，同框镜头里经常互换。下一集应该在场景参考图里画好固定站位，或在提示词里写死站位。

## 五、发布阶段的坑（2026-11-09 第 1 集上线）

| 现象 | 原因 | 做法 |
|---|---|---|
| Shorts 只能截字幕帧当封面 | 竖版没有专门的封面 | Codex 生图，参考帧取自视频，保证同一个人；见 `channel/频道方案.md` 第 9 节 |
| `codex exec` 卡住不动 | 它在等标准输入 | 命令末尾加 `< /dev/null` |
| 自定义缩略图、简介里的链接不能用 | 新频道没做手机号验证 | 用户本人去 youtube.com/verify 验证一次 |
| 向导里点了「发布」也拿到了链接，视频却还是私享 | 新频道 Shorts 上传后第一次发布没生效 | 以公开播放页的 `playabilityStatus` 为准，`LOGIN_REQUIRED` 就从「编辑草稿」再发布一次 |
| Studio 显示「无权查看」 | 浏览器同时登录多个 Google 身份，默认落在别的账号 | 右上角头像 → 切换账号 → MakeItRap |
| 网站从 main 部署会抹掉线上内容 | 线上跑的是未合并的 codex 分支 | 部署前对比线上页面和 `wrangler deployments list` |
| 点「发布」后弹「我们仍在检查你的内容」 | 版权/政策检查要等标清处理完 | 原创内容直接点「仍然发布」，发完照样用公开页核实（第 2 集 4 条都是这样发的） |
| 置顶评论读出来少了 emoji | YouTube 把 emoji 渲染成 `<img alt>`，`innerText` 读不到 | 查 `#content-text img` 的 `alt`，不要重发 |
| 置顶菜单点了没反应 | 菜单项和确认框是自绘组件，DOM `click()` 不触发 | 截图后按坐标点「置顶」和确认框的「置顶」，刷新看「已由 @makeitrap 置顶」 |
| 长视频上传 270 MB 要约 30 分钟 | 本地上行带宽 | 先填长视频，同时在第二个标签页把 3 条 Shorts 传完发完；「相关视频」可以在长视频还没公开时就选 |

## 七、第 2 集新增（napoleon-vs-wellington，2026-11-10，共 16.9 CCU）

1. **`qa.py` 对 73 帧短镜头误报**：音轨相关度 0.87-0.99、首 1 秒窗口 <0.9 就判 `ok: False`；用 mediapipe 唇形打分器复核，口型并不比 90 帧以上的差。不要因此重抽。
2. **静态反应镜头会在片段中间硬切**（特写 → 全景，约 1.4-1.6 s），开头也不一定是摆拍。每个镜头的入点要看逐帧拼图来挑，写进 `build_storyboard.py` 的 `REACT_IN_BY`，不能只用一个全局 `REACT_IN`。
3. **台下观众要动起来**：远景不给任何场景参考图，只用文字描述环境（底部 1/3 帧差 1.36 → 5 左右）；近景/中景保留半张舞台图，一致性更重要。
4. **道具要用名词点名**："laurel-leaf crown" 被画成镶宝石的王冠，改成 "golden laurel wreath" 才对；每个道具只写给它的主人（"the spyglass only to Wellington"）。
5. **G4 分配时报 503 不计费**，只能等；A100/H100 跑不了 H3（NVFP4 编码器只在 Blackwell 上原生）。后台重试脚本只对分配阶段的 503 重试，并设截止时间。
6. **两段主歌首尾相接时字幕重叠**（A16 → B09）：`package.py` 里一段的最后一句原本固定多留 0.5 s，现在不超过下一句开始前 0.07 s。
7. **缩略图名字太长出框**（NAPOLEON / WELLINGTON）：`make_brand_assets.thumbnail()` 按总宽自动缩放到画面 92%，短名字保持原大小（第 1 集缩略图逐像素不变）。
8. **桌面版 Studio 可以直接给 Shorts 上传自定义竖版封面**（详细信息 → 缩略图 → 上传文件），不用等发布后再改。

1. **换脸部参考图后必须同步 `episode.json` 和 `build_storyboard.py`**：牛顿从假发版换成自然披肩长发版（`a_face_clean.png`）后，如果 `episode.json` 的 `a.look` / `a.prop` 和 `build_storyboard.py` 的 `raw` 镜头描述里还留着 `"silver-grey curled wig"`，H3 会在过肩/双人镜头（`A03`、`A08`）里按文字重新长出白假发。改定妆照时必须同步清掉所有文字里的旧发型描述。
2. **多条 Shorts 合并同一次 G4 会话渲染**：`run_rap_battle_remote.py` 的 `ep` 参数改为 `nargs="+"`，一次挂载模型即可顺序跑完 `s1_dydx`、`s2_lion`、`s3_history` 共 12 个竖版镜头（仅耗 `1.79 CCU`，省去 2 次冷启动）。

5. **英文剧集 `cover.py` 标签**：`episode.json` 中 `language == "en"` 时，`cover.py` 自动使用 `"AI GENERATED"` / `"RAP BATTLE"`，不再混入中文角标。

## 九、电影级实拍质感升级（Realism V3，2026-11-11）

针对前 3 集相比对标爆款《曹操VS刘备！》（`BV1T9Hy6hEwD`）仍有「AI 数字感较强」及上文第 四.3 条遗留的「768p 放大偏软 / 暗部死黑与彩噪」问题，完成了三轮控制变量盲测并沉淀出 **Realism V3 标准管线**（完整诊断、踩坑边界与模板见 **[经验沉淀_电影实拍质感升级.md](经验沉淀_电影实拍质感升级.md)**）：

1. **参考图光学预处理（`scripts/film_optics.py`，0 CCU）**：特写镜头喂 `f/11` 全清晰 `stage_a/b.png` 会迫使 H3 画出 10px 刀刻五官的微缩假人；用 `r=16`（`arena_crowd=True`）在线性光空间做圆盘光圈卷积并压暗上方冷色窗户，既彻底消除五官恐怖谷，又保留沸腾学者剪影与 `2700K` 暖烛台圆盘散景（实测 `r=28` 会把观众抹成空黑棚，`r=10` 仍露五官，`r=16` 最优）。
2. **双色温电影布光（解决平光塑料感与冷光死灰脸）**：正面平光像棚拍 CG，纯 `5600K` 冷光让肤色发青发灰（`SatMean=0.21`）；改用 `3200K` 暖钨丝伦勃朗侧主光（`4:1` 光比，红润血色肌肤 `SatMean=0.28–0.30`）+ `5600K` 冷银顶逆发丝光 + 人像参考图 `warm_skin_boost=0.18`。
3. **底模与贴唇前景麦（`--realism-v2 --steps 12`）**：从 `convrot` 8 步切至 `Singularity v1.3` 12 步去皮肤油光，手持麦从胸口端麦改为下唇下方 1 英寸 45° 斜举贴底边前景透视，口型锁音相关度保持 `0.969–0.998`。
4. **单通 1080p 胶片直出（`assemble.py --film` + `package.py --film --1080p`）**：废除 `768p` 双重压暗与二次加彩噪，先 Lanczos 升至 `1080p`，再单通施加 `0.76` 高阈值 `Pro-Mist 1/8`（`0.08`）、紧致 Vision3 S 曲线（`0/0.034`，`P05=6.2–7.7`，死黑从 `18%–33%` 降至 `<4.5%`）与纯亮度细银盐颗粒（`c0s=3:c1s=0:c2s=0`）。角标禁放彩色 Emoji（如 `🔬` 会变方框，统一用 `◆`）。
5. **默认不加 `Tessera 2.7K`**：实测加 `--tessera-2k` 单镜头从 `~0.51 CCU` 涨到 `~2.46 CCU`（贵约 4.8 倍），压成 1080p 流媒体后肉眼差距极小，日常生产一律关闭，单集维持 `~12–16 CCU`。

## 十一、第 5～6 集新增：Suno 歌词润色与游戏原声还原管线（tommy-vs-cj / arthur-vs-geralt，2026-11-12）

针对游戏/影视经典角色观众对原版配音有强肌肉记忆的需求，完成了从「Suno 简单变调」到「L4 双擎原声还原」的标准升级（完整声学指标、踩坑边界与命令模板见 **[经验沉淀_音乐制作与游戏原声还原.md](经验沉淀_音乐制作与游戏原声还原.md)**）：

4. **区分 `if_f0=1` 与 `if_f0=0` 模型并做单次多档位扫描**：带音高条件模型（如 Arthur `morgan_700e_69300s.pth`）按 `pitch_lvl` 精确移调（`-2 st` 落点 `120.5 Hz` 贴合 Roger Clark 原声 `122.2 Hz`）；纯语调模型（如 Geralt `Geralt_e300_s6000.pth`）原生直锁 Doug Cockle 低沉基频（`90.2 Hz` vs 原声 `86.5 Hz`）。L4 内存一次跑完 5 档仅多花 25 秒，本地用 `--remaster-only --pair-a ... --pair-b ...` 零成本自由混搭。
5. **参考干音三道纯净门控与文件契约**：测男低音 `F0` 前必须加 `< 270 Hz` 低通防泛音八度误判，并用 `P15 < -37 dBFS` + 逐句 `F0` 门限剔除混剪 BGM 与第二说话人（如 Ciri/NPC 对白）；**`song.mp3` 永远保留未裁剪原曲**，转换母带（`-14.5 LUFS / -0.2 dBFS`）仅写入 `音乐_最终.wav`、`work/music_final.wav` 与 `work/vocals_final.wav`。
